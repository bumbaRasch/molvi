# UI Internationalization (i18n) — Design Spec

**Date:** 2026-08-04
**Branch:** phase2 (additive feature, executed after Task 20 sounds)
**Scope:** Translate the ENTIRE molvi user-facing UI — Settings window, dictation
overlay, and system-tray menu — into all 36 distinct Nemotron languages; add a
language picker. Settings + overlay are frontend; the tray is Rust-side. No ASR
changes (recognition stays engine-driven).

## 1. Goal

molvi's Settings UI is currently Russian-only. The Nemotron engine supports 40
language-locales (= 36 distinct languages, since locale pairs like en-US/en-GB
share one UI translation). This feature makes the UI fully multilingual: a
language picker, all UI strings translated, default English, instant switching.

"Better than competitors, maximally performant": instant switch (pure object
lookup, zero latency), zero new dependencies, native-language (endonym) labels
so users find their language in their own script.

## 3. Architecture (no i18n library — plain static dictionary)

**Why no library:** ~100 keys × 36 languages. A plain TS object is the fastest
possible lookup — a single property access. Any library (i18next, etc.) adds
overhead and a dependency for nothing. "Maximally performant" = `dict[key]`.

**Files (new):**
- `src/i18n/locales.ts` — `export const locales: Record<Lang, Dict>` where
  `type Dict = Record<string, string>`. ONE bundled object, all 36 languages.
  ~3600 strings total, ~30 KB gzipped, loaded once from local disk (Tauri
  asset). Bundling all (vs lazy per-language fetch) makes switching **instant**
  — no async fetch on switch, which is the competitors' weakness.
- `src/i18n/index.ts`:
  - `export type Lang = "ar"|"bg"|...|"zh"` (36-member string union).
  - `export const LANGUAGES: ReadonlyArray<{ code: Lang; label: string }>`
    — sorted by `code`, `label` = endonym (from the table above).
  - `let current: Lang` + `getCurrentLang()` + `setCurrentLang(lang, rerender)`.
  - `export function t(key: string): string` →
    `locales[current]?.[key] ?? locales.en[key] ?? key` (fallback chain:
    current → English → raw key). The raw-key fallback makes a missing
    translation visible but never crashes.
  - `RTL_LANGS = new Set(["ar","he"])` — the only two RTL languages of the 36.
    On `setCurrentLang`, set `document.documentElement.dir = rtl ? "rtl" :
    "ltr"` AND `document.documentElement.lang = code`. Setting `dir=rtl` on the
    root mirrors most of the layout for free (flex row puts the sidebar on the
    right, text-align flips, form controls mirror). This is the one-change RTL
    trigger; the work below makes it actually correct.

**Modified:**
- `src/settings/store.ts` / `types.ts` — `Settings.ui_lang: string` (default
  `"en"`). The language select writes through the existing patcher.
- `src/settings/main.ts` — on boot: read `settings.ui_lang` → `setCurrentLang`
  before first render; build the sidebar including the pinned language row;
  expose a `rerender()` that re-invokes the active section's builder + rebuilds
  sidebar labels on language change.
- All 9 section builders + `icons.ts` (nav labels) — replace every string
  literal with `t("namespace.key")`.
- `src/overlay.ts` — import the SAME `i18n` module; on show, read `ui_lang` from
  settings and translate the ~5 phase captions (listening/transcribing/working/
  polishing/recording). Shared dictionary → zero duplication with Settings.
- `src/settings.css` — the pinned sidebar language row (label + select); minor
  RTL accommodation if needed (the existing layout is flex/grid, mostly
  dir-agnostic).

**Tray (Rust-side i18n — `src-tauri/src/tray_locales.rs`):**
The tray is built in Rust, so it has its own small typed dictionary for the ~8
tray strings (Status/Toggle/Settings/History/Quit + tooltip states + recording
indicator), same 36 language codes:
```rust
pub struct TrayStrings { pub settings: &'static str, pub history: &'static str,
    pub quit: &'static str, pub toggle: &'static str, pub status_ready: &'static str,
    pub status_warming: &'static str, pub recording: &'static str, /* ... */ }
pub const TRAY_LOCALES: &[(&str, TrayStrings)] = &[
    ("ar", TrayStrings { settings: "الإعدادات", ... }),
    /* ... 36 entries ... */
    ("en", TrayStrings { settings: "Settings", ... }),
];
/// Linear scan (36 entries, rare menu rebuild) → fallback to English.
pub fn tray_t(lang: &str) -> &'static TrayStrings;
```
The named-struct form makes every language carry every key (compile-checked) —
a missing translation is a build error. `tray.rs` builds the menu via
`tray_t(ui_lang)`; `set_settings` gains a new live-apply arm: on `ui_lang`
change, rebuild the tray menu + tooltip. (Mirrors the existing hotkey/autostart/
history live-apply arms.) No build-time codegen; the tray keys are few and
stable, so a separate Rust table is simpler than a shared-source pipeline.

**Settings persistence:** add `pub ui_lang: String` to `settings.rs` (the
top-level `Settings` struct, `#[serde(default)]`, default `"en"`). Saved via the
existing `set_settings` IPC — no new command. No backward compat needed (owner
directive): an old settings.json without `ui_lang` gets `"en"` via serde default.

## 4. Sidebar language picker (pinned bottom row) — owner's choice (a)

At the **bottom of the sidebar** (below the 9 nav items), a pinned row:
`[Language label] [select ▾]`. Always visible — the user switches language
anytime without navigating. The select lists all 36 languages (endonym labels,
ISO-sorted), with the current language selected. On change: persist
`ui_lang`, `setCurrentLang`, re-render the active section + sidebar labels.
Instant. (This is the slicker UX vs a navigated "Language" section; owner
chose the pinned row.)

## 5. Canonical key set (frozen by Task 1, the source for all translators)

Namespaces mirror the surfaces + shared strings. Task 1 produces the definitive
English source of truth (`locales.en` for settings+overlay, `TRAY_LOCALES` "en"
entry for the tray) and the Russian migration (`ru`); the key list is FROZEN at
Task 1's commit. Translation agents work only from the frozen English source —
never edit keys, only values.

Representative namespaces (Task 1 enumerates the exact keys):
- `nav.*` — the 9 sidebar item labels (recognition, microphone, text,
  dictionary, history, hotkey, overlay, updates, about) + the language-row
  label.
- `recognition.*`, `microphone.*`, `text.*`, `dictionary.*`, `history.*`,
  `hotkey.*`, `overlay.*` (Settings section), `updates.*`, `about.*` — each
  section's titles, labels, placeholders, alerts.
- `common.*` — shared buttons/words: Обзор/Сбросить/Отмена/Добавить/Удалить/
  Импорт/Экспорт/Сохранить/«Проверить громкость»/«Стоп»/«Записать сочетание»/
  error prefix, empty-states, etc.
- `ovl.*` — the overlay phase captions (listening/transcribing/working/
  polishing/recording).
- `tray.*` — the tray strings (Status/Toggle/Settings/History/Quit + tooltip
  ready/warming + recording indicator); these live in the Rust `TrayStrings`
  struct, conceptually the same key namespace.

## 6. Implementation decomposition (SDD)

**Task 1 — Architecture + EN/RU (main implementer):**
Build the i18n system: TS `i18n/index.ts` + `i18n/locales.ts` (settings + overlay
keys, `en` + `ru`), Rust `tray_locales.rs` (`TrayStrings` + `TRAY_LOCALES` with
`en` + `ru`), `settings.ui_lang` (Rust + TS types), the pinned sidebar language
row, the `rerender()` switch + RTL dir, overlay caption i18n, tray menu built
via `tray_t(ui_lang)`, and the `set_settings` live-apply arm that rebuilds the
tray on `ui_lang` change. Migrate EVERY UI string (settings + overlay + tray) to
keys with English values + Russian migrated from the current UI. FREEZES the key
manifest (nav/recognition/.../about/common/ovl/tray). Gate: `cargo fmt`/`clippy
-D warnings`/`test` (settings.rs field + tray_locales, 82+ tests green), `npx
tsc --noEmit`, `npm run build`; manual smoke = switch EN↔RU: all Settings
sections + overlay captions + tray menu re-render in the chosen language; ar/he
flip RTL.

**Tasks 2..N — Translations (dedicated quality agents, parallel):**
The remaining 34 languages, translated from the frozen English source — BOTH the
TS `locales[lang]` entry (settings + overlay + common keys) AND the Rust
`TRAY_LOCALES` entry for that language. Locale files/entries are independent per
language → no file conflicts → parallel agents are safe. Dispatching-parallel-
agents: group the 34 into ~4 batches of ~8-9 languages for focused, high-quality
output (one agent doing all 34 in a single dispatch would degrade quality and
hit output limits). Each agent: translate every TS key + every `TrayStrings`
field, preserve placeholders/interpolation markers, verify native UI terminology
(may web-search conventions per language), keep each file's structure exactly.
The owner explicitly wants a dedicated agent for best translation quality.

Each translation task gate: `tsc --noEmit` + `npm run build` (TypeScript
validates `locales.ts` shape — a missing/extra key is a type error against the
frozen `Dict`) AND `cargo build --manifest-path src-tauri/Cargo.toml` (the Rust
`TrayStrings` struct makes a missing field a compile error).

## 7. Constraints (HARD)

- **No new dependencies.** No i18n library. Plain object + lookup.
- **No backward compat** (owner directive): `ui_lang` is a clean new field;
  missing → `"en"` via serde default. No migration, no version bumping.
- **Privacy §10.1:** frontend-only; the 82-test privacy suite is untouched.
- **RTL correctness (ar, he):** the two RTL languages must render mirrored, not
  broken. Concretely: (1) `dir=rtl` flip (above); (2) CSS audit — replace any
  physical `left`/`right`/`margin-left`/`text-align:left` with logical
  `inline-start`/`inline-end`/`margin-inline-start`/`start` so the layout
  mirrors with `dir`; the recent CSS cleanup already moved block-axis props to
  logical — Task 1 audits the inline axis too; (3) the overlay sets its text
  alignment from the current dir; (4) any inline style in TS that hardcodes a
  side uses the logical equivalent. The tray menu is OS-rendered (Win32) — RTL
  is handled by the OS, no app work. Task 1 gate includes an **ar + he RTL
  smoke** (select العربية, then עברית: sidebar flips to the right, text
  right-aligned, no clipped/overlapping controls).
- **Blaze (no regression):** RTF, cold-start, RSS, NSIS size unaffected.
  `locales.ts` is ~30 KB gzipped bundled UI asset — negligible for a desktop
  app loading from local disk.
- **Ponytail:** smallest diff; reuse the existing `patcher`/`store`/section
  builder pattern; the only new structural element is the pinned sidebar row +
  the `t()` indirection.

## 8. Out of scope

- Recognition-language coupling (Nemotron keeps `set_target_lang("auto")`;
  GigaAM stays ru-only). The picker is UI-display-only.
- Fine-grained RTL typography polish beyond correct mirroring + text alignment
  (font choices, bidi punctuation edge cases) — deferred; the gate is "renders
  mirrored, no clipping/overlap" for ar + he.
- Translating log messages / Rust error strings (those are metadata-only,
  never user-facing; privacy discipline keeps them metadata).
